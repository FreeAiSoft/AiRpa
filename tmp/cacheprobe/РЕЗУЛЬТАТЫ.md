## 2. Первый кадр (то, ради чего всё)

* Свой словарь поставлен **до** `new DesignerMetadata().Register()` и до первого WF-контрола:
  плита/рамка/подпись активности приходят из наших кистей **без единого прохода темизации**
  (`элементов на НАШЕЙ кисти: 10`, фон `#FF1E1E1E` там, где WF по умолчанию `#FFFFFFFF`/`#FFE9ECEE`).
* Шаблоны, которые впервые разбираются **позже в процессе** (`If`, `Parallel` — аналог
  «перетащил активность в конструктор»), тоже сразу в палитре: сценарий «поздняя активность» —
  все 4 активности на наших кистях, ни одного светлого кадра.
* Контрольный прогон без установки (`probe1 / control`) даёт эталон WF — светлые плиты, то есть
  разница именно от установки, а не от чего-то ещё.

## 3. Что НЕ работает наивно: кисти замораживаются

* В момент `new WorkflowDesigner() + Load()` WPF **замораживает** наши кисти (`IsFrozen=True`) и
  ставит нашему словарю `IsReadOnly=True`
  (WPF: `StyleHelper` — «Freezable within a Style or Template should have been frozen by now»;
  `ResourceDictionary.IsReadOnly` → `SealValues()`).
* Следствие 1: `brush.Color = …` падает `InvalidOperationException` («объект в состоянии только чтение»).
* Следствие 2: `dict[key] = newBrush` падает `InvalidOperationException: ResourceDictionary доступен
  только для чтения`. Сеттер `IsReadOnly` — `internal`, только рефлексией.
* Следствие 3: наивная «смена темы мутацией кистей» (то, что закладывалось в вариант 1) — **не вариант**.

## 4. Рабочая замена: кисти с привязкой (`Binding` на `SolidColorBrush.ColorProperty`)

* Такая кисть `CanFreeze=false` → WPF не замораживает её, а делает **клон на элемент**
  (`StyleHelper`: `requiresInstanceStorage = true`), и клон **копирует выражение привязки**.
* Проверено: первый кадр — из источника (тёмная палитра), `IsFrozen=False` у кистей в словаре.
* Смена **только свойства источника** (одного объекта) перекрашивает уже созданные элементы:
  `probe3` — 4 ключа (фон/рамка/подпись/поверхность), `probe4` — **все 59 ключей** на 5 разных
  активностях (`Sequence`, `If`, `WriteLine`, `Parallel`), `bg` сменился с `#FFFFFFFF` на `#FFFAFAFA`,
  рамка — на `#FFC86400`, ни одного обхода дерева, ни одного нового `Apply`.
* Цена: один клон кисти на элемент на ключ (у активности реально 2–3 кисти) — на порядки дешевле
  любого прохода по дереву.

## 5. Границы покрытия вариантом 1

Покрывается (ключи `ColorResources.xaml`): плита активности, рамка, подпись, выбранное состояние,
поверхность дизайнера, shell bar, статус-бар, контекстные меню, `GridView*`, `OutlineView*`,
аннотации, коннекторы флоучарта, разделители `Parallel`.

НЕ покрывается:
* **инспектор свойств** — его ключи (`PropertyInspector*BrushKey`) живут в
  `WorkflowDesignerColors.DefaultColors` → `FontAndColorResources`, а тот добавляется в
  `Application.Resources` в конструкторе `WorkflowDesigner`; остаётся текущий механизм
  (`PropertyWindowStyleHelper` + при желании официальный `PropertyInspectorFontAndColorData`);
* **Toolbox** — `ToolboxDefaultTemplate.xaml` не ссылается на `ColorResources`;
* контролы студии (`RoslynExpressionEditor.xaml` использует `{DynamicResource WorkflowViewElementBackground}`
  и `DesignerViewBackground}` — их берёт словарь приложения, как и сейчас).

## 6. Что нужно для реализации (чек-лист)

1. Точка установки в студии: `App.StartupCore` **перед** `new EntryPoint().Run()`
   (после `StudioBrushes.ApplyToApplication()`, `StudioFonts.ApplyToApplication()`,
   `WfDesignerTheme.ApplyToApplication()`). В этот момент ни одного WF-контрола ещё не создано.
2. Один рефлексионный хват: `typeof(CachedResourceDictionaryExtension).GetField("Cache", NonPublic|Static)`;
   если поля нет — работать по-старому (fallback + запись в лог).
3. Свой словарь: `MergedDictionaries.Add(WF ColorResources)` + переопределённые ключи
   (кисти с привязкой на `ThemeColor`-источник из `StudioPalette`). Поставить по обоим URI.
4. Смена темы: обновить `ThemeColor.Value` по ключам из палитры — без обхода дерева. Для непокрытых
   мест (инспектор, контролы студии) остаются текущие механизмы.
5. Страж-тесты: поле/оба URI на месте и запись проходит; словарь наш после загрузки дизайнера;
   `IsFrozen=False` у кистей; «нет светлой плиты на первом кадре» (снимок/RenderTargetBitmap).
6. Из текущего кода после внедрения уходят: пост-покраска активностей (`WfActivityTheme`),
   «нейтрализация светлых кистей» и `LayoutUpdated`-дозаказы по активностям
   (`WfThemeStyles` / `WfVisualTreeThemer` в части активностей). Инспектор и контролы студии — без изменений.
