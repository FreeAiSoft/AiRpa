| Симптом | Причина в коде | Следствие |

## 2. Что сделано сейчас (код в репозитории)

| Файл | Роль |
|---|---|
| `AiRpaStudio\Core\Validation\DesignerValidationScope.cs` | единый обход модели с **адресами**: активность добавляется в результат, обёртка WF (`ActivityAction`, `ActivityDelegate`, `FlowNode`, `Catch`, `State`, `PickBranch`, `Transition`, кастомный контейнер) обходится без добавления; `Variable`/`LocationReference`/`Argument` и всё вне `System.Activities*` — не обходятся; циклы отсекаются по идентичности узла |
| `AiRpaStudio\Core\Validation\ModelItemScopeNode.cs` | адаптер обхода над настоящим `ModelItem` (чтение свойств через try/catch: одна нечитаемая активность не обрывает проход) |
| `AiRpaStudio\Core\Validation\ExpressionEnvironment.cs` | **снимок** окружения выражения (аргументы + переменные в области видимости + блок `using`); собирается на UI-потоке, читается в фоне |
| `AiRpaStudio\Core\Validation\ActivityExpressionCheck.cs` | снимок одной проверки (адрес, аргумент, вид проверки, текст, типы) и `ActivityValidationError` (адрес + сообщение) |
| `AiRpaStudio\Core\Validation\ExpressionErrorEvaluator.cs` | правила «выражение корректно» без `ModelItem`: `OutArgument`, литерал, выражение, правая часть `Assign`; сообщения — дословно прежние |
| `AiRpaStudio\Core\Validation\RoslynExpressionCompiler.cs` | единственная точка касания Roslyn (`IExpressionCompiler`) |
| `AiRpaStudio\Core\Validation\DesignerValidationPass.cs` | поколения проходов: отмена предыдущего, отбрасывание устаревшего результата, состояния «выполняется / выполнено / **не выполнено (причина)**» |
| `AiRpaStudio\CSharpExpressionEditor\DesignerValidator.cs` | три фазы: снимок модели и проверок (UI) → компиляция (фон) → иконки по адресам (UI, только для текущего поколения) |
| `AiRpaStudio\CSharpExpressionEditor\RoslynExpressionValidator.cs` | статический вход `CheckExpression(text, ExpressionEnvironment)`, компиляция на вызов, полное имя типа в C#-синтаксисе (`System.Collections.Generic.List<System.String>`) |

Порядок прохода:

```
тик таймера (UI): ValidationSchedule.ShouldValidate
  → DesignerValidationScope.Collect(Implementation)          — адреса + ModelItem
  → снимок окружения и проверок (ActivityExpressionCheck)     — без компиляции
  → ValidationService.ValidateWorkflow()                     — WF-часть, остаётся на UI
  → DesignerValidationPass.Begin() → Task.Run(...)           — поколение N
фон: ExpressionErrorEvaluator.Evaluate(checks, compiler, token)
  → TryComplete(N): false → результат выброшен (текст уже другой)
UI (Dispatcher.BeginInvoke): IsCurrent(N) → SetValivationErrorsToModelItem по адресам
```

**Почему WF-часть осталась на UI.** `ValidateWorkflow()` наполняет `ModelItem.ValidationState`, по
которому иконки рисует сам WF; переносить его в фон нельзя. Его цена **не измерялась** — это шаг 0
ниже. Если замер покажет, что он и есть узкое место, следующим шагом будет отчёт
`StudioWorkflowOutlineService.BuildOutline` по снимку текста в фоне (в студии уже есть headless-загрузка
`ActivityXamlServices.Load` с `CompileExpressions = false` — `WorkflowValidationGate`).

## 4. План `UI-09` (баг `new List<string>`, теряется угловая скобка)

Симптом: при импорте параметра/переменной значение `new List<string>()` доезжает без `>`.
Гипотеза проверяется по коду, а не на глаз — три кандидата:

1. **XAML-экранирование**: `<` и `>` в атрибуте/элементе `ExpressionText` требуют `&lt;`/`&gt;`;
   запись без экранирования рвёт разметку или обрезается парсером. Смотреть: `WorkflowXamlSerializer`,
   `WorkflowCanonicalizer`, места записи `ExpressionText`.
2. **Обрезка текста выражения** при чтении (`TextExpression`/`ExpressionText` + `Trim`) или в
   нормализаторе выражений — сравнить длину до/после.
3. **`Type.Name`/сокращение типа**: если значение попадает в дерево как тип, а не как строка
   выражения, `List<string>` собирается заново и теряет аргумент типа (та же категория ошибки, что
   исправлена в `RoslynExpressionValidator.CSharpTypeName` — там псевдоним типа был «List\`1»).

Шаги: (1) тест-воспроизведение: XAML-фикстура с `new List<string>()` в аргументе → чтение → запись →
повторное чтение, сравнение байт-в-байт; (2) прогон через настоящий конструктор
(`Design\DesignerBenchProxy`) на фикстуре; (3) фикс в **единственном** найденном месте, без второго
пути сериализации; (4) негатив: снять экранирование/обрезку → тест краснеет. Оценка — 0,5 дня после
воспроизведения.

**Что проверено кодом (09.11.2026), `ArgumentExpressionEscapingTests` (3 теста):**

1. гипотеза «XML-экранирование» **не подтвердилась**: в файле выражение пишется как
   `new List&lt;string&gt;()` (`GenericTypeExpression_IsEscapedInXaml`), а разбор XML возвращает ровно
   `new List<string>()` (`GenericTypeExpression_SurvivesReadBack`);
2. гипотеза «обрезка текста при чтении» на пути генерации **не подтвердилась**: совпадение символ
   в символ, документ по-прежнему проходит гейт (`DocumentWithGenericTypeExpression_PassesGate`);
3. попутно выяснена форма хранения выражения у WF: элемент `<mca:CSharpValue>` содержит дочерний
   `<mca:CSharpValue.Result>` (объявление `OutArgument`), а текст выражения идёт **после** него как
   смешанное содержимое. Любой код, который читает или пересобирает `CSharpValue` через
   `XElement.Value` (или переписывает элемент целиком), теряет этот хвост — единственное найденное
   место, где `>` может «пропасть» при импорте.

**Осталось:** воспроизведение в интерактивном конструкторе — нужен точный шаг (что именно значит
«импорт параметра»: `DynamicArgumentDialog` у активности `RunScript`, панель «Аргументы» конструктора
или импорт через `ArgumentDesigner`). Путь генерации/сериализации чист, поэтому фикс без шага
воспроизведения будет угадыванием.

## 8. Шаги 0 и 5: что показал прогон на живом конструкторе (09.11.2026)

Стенд: `DesignerBenchProxy.ValidationPassScenario`, тесты `BackgroundValidationRealDesignerTests` (13).
Документ нагрузки: 105 активностей по `WorkflowInspectionServices`, **114** в области валидации
(с телами и ветками), **112** проверок выражений, **4** замечания. Три из них — намеренные ошибки
в `ForEach.Body` (`ActivityAction`), `Pick.Branches[0].Action` (`PickBranch`) и `If.Then`; корректное
тело цикла (`item` — аргумент делегата) ошибкой не помечено, то есть поток ложных замечаний не открыт.

| Фаза прохода | Сейчас | Было |
|---|---|---|
| обход модели с адресами (UI) | 6,5 мс | 6,5 мс |
| снимок окружения и проверок (UI) | 25,1 мс | 25,1 мс |
| `ValidationService.ValidateWorkflow()` (UI) | **0,1 мс** | 0,1 мс |
| применение иконок по адресам (UI) | 11,2 мс | 11,2 мс |
| компиляция выражений Roslyn | **1118,9 мс — фоновая задача** | 1118,9 мс — UI-поток, на литерал дважды |
| **итого занятость UI-потока** | **42,8 мс** | **≥ 1161,7 мс** |

Наибольшая пауза диспетчера за проход — **55,4 мс** (тик пробника 10 мс), то есть конструктор
не «замирает» на время компиляции.

**Ответ на открытый вопрос из §2:** `ValidateWorkflow()` — не узкое место (0,1 мс на 114 активностях).
WF-часть остаётся на UI-потоке; переписывать её на headless-отчёт `StudioWorkflowOutlineService.BuildOutline`
по снимку текста не требуется. Это зафиксировано, чтобы вопрос не поднимался заново без новых данных.

**Ограничение стенда (важно для чтения тестов).** Вьюхи строятся только для видимой части документа:
из 114 адресов вьюха есть у 15 (99 — «без вьюхи», `validationVisuals` не найден ни на одном
построенном). Кроме того, `Pick` показывает ветки только после раскрытия, `If` — только `Then`-панель,
поэтому вьюхи `Branches[0]/Action` и `Then/Activities[0]` headless не создаются вообще. Отсюда разделение
доказательств:

* **вложенность ошибки** доказывается адресом замечания (`errors found inside …`) для всех трёх
  контейнеров — это и есть «валидация кастомных активностей»;
* **иконка** доказывается на теле `ForEach` (оно рендерится inline, вьюха есть): в подсказке иконки
  виден текст ошибки выражения (`missingVariableInsideBody`), а у корректного тела цикла того же
  сообщения нет. Проверять одну видимость `Border` нельзя: WF рисует такую же иконку по своему
  состоянию, и «видимость» ничего не говорит о том, чья она.

Чтобы отличать свою иконку от иконки WF, в отчёт стенда добавлены `AddressToolTips` (адрес → текст
подсказки): у студии это `ValidationIconState.ComposeToolTip` со своими сообщениями.

Журнал замеров на конкретной машине: `%TEMP%\AiRpaStudio-validation-baseline.txt` (пишется сценарием).
